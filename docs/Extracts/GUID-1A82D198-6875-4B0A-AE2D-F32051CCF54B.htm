DWF Publishing

 
 
 

When creating a DWF file, you may elect to turn Granular pipeline output on in the P&ID Publish Options dialog. This causes dwf output to contain granulated information. As part of the publishing process, temporary AcPpLineSegments are created representing granular form.

When publishing P&ID information, these temporary objects can be modified to provide granular sequenced metadata.

A Tee appears as an AcDbPoint in the published output.

The diagram below allows you to describe the relationship between saved AcPpGranularObjects, sequence number, and the temporary entities that are used for DWF publishing.

pipe sequence (1) to (13)

The horizontal line 12”-C3-P-5L contains five AcPpLineSegment entities in the drawing. During granular DWF publishing, seven AcPpLineSegment (1,3,5,7,9,11,13) temporary, memory-only objects are generated. Two temporary AcDbPoint (2,12) objects are generated for the two Tees. Inline sequence numbers (4,6,8,10) do not generate temporary entities.

Note the HNNNN handles shown represent AcPpGranularObjects that were previously saved as dictionary items. It is important to understand that those AcPpGranularObjects are not generated as part of the publishing process. The handles represent the state of the sline as it was when saved to the dictionary earlier and may be stale.

There is no direct link between the saved AcPpGranularObjects and the temporary entities that are decomposed during publishing. Only the sequence number applies to both, and it is left to developers to reconcile changes that may have been made since the save.

During DWF publishing, developers may review each of these temporary entities from OnGranularEntityAppended of the AcPpGranularDwfReactor derived class. The following class declaration could be used to define a reactor: 

//C++
class MyGranularDwfReactor : public AcPpGranularDwfReactor {
   void OnDecomposeBegin(AcPpLineSegment*& pLineSegment);
   void OnGranularEntityAppended(AcDbEntity*& pEntity, int nSequence);
   void OnDecomposeEnded(AcPpLineSegment*& pLineSegment);
};

After creating an AcPpGranularDwfReactor derived class, the following code initializes the reactor using the P&ID services object: 

//C++
MyGranularDwfReactor *preactor=new MyGranularDwfReactor;
AcPpGranularDwfManager *pgdm = AcPnIDServices::getPnIDServices()->getGranularDwfManager();
pgdm->addReactor(preactor);
NOTE:Disable background publishing unless the module demand loads with the application. Background publishing runs in new execution context.
