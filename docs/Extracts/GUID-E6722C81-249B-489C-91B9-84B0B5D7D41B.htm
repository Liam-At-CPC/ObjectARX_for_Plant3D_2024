Plant Project

 
 
 

Developers can automate project setup using functions that provide access to the Project Manager.

The Project class contains services to access project-level information. This includes the project settings, a list of the drawing file names in the project, and links to other data files and objects such as the symbol and style library.

PlantProject contains a list of Project objects called ProjectParts. The list is unique by most-derived type. For example, a PlantProject can contain none or one PnIdProject. It can also contain none or one PipingProject, and so on.

Because project parts are unique by type, the ProjectPartCollection may be keyed by type. The following code obtains the PnIdProject from the current PlantProject. 

//C#
using Autodesk.ProcessPower.PlantInstance;
PlantProject oPP=PlantApplication.CurrentProject; //static member
Project oPrj = oPP.ProjectParts["PnId"];
PnIdProject oPnIdProject = (PnIdProject)oPrj; //cast is guaranteed

PlantProject may also be loaded from and saved to Project.xml.

The Project class also provides access to the Data Links Manager.

PnPProjectUtils makes it easy to get information about the active drawing and active project. The following code first checks that current drawing is either a PnId drawing or a Piping drawing, then gets the active Project. 

//C#
Editor ed = Application.DocumentManager.MdiActiveDocument.Editor;
string dwgtype = PnPProjectUtils.GetActiveDocumentType();
if (dwgtype != "PnId" || dwgtype != "Piping")
{  //"PnId", "Piping", "Ortho", "Iso"
   ed.WriteMessage("This drawing is not a P&ID or 3D Model in the current project.\n");
			return;
}
Project prj = PnPProjectUtils.GetProjectPartForCurrentDocument();
NOTE:There are no APIs to control Project Manager UI-level operations.
